# 一份配方、一张实验卡、一次结果回填

## 1. 开跑前

1. 查[索引](实验索引.md)和[运行目录](逐次运行目录.md)，写明相关实验ID和不重复的理由。
2. 用[模板](记录模板.md)写问题、类型（诊断/性能优化/机制消融）、唯一变量、参照、机器/seed和判定。
3. 公共配方引用[B0](baselines/B0.md)；新配方另登记B1，不覆盖旧记录的含义。
4. 本地测试/代码审查独立完成。记录CPU检查与真实CUDA测试的区别；正式脚本不自动跑测试或性能断言。
5. 提交对应代码、配方和实验卡，再给脚本、提交号、机器顺序与时间估计。不自动启动服务器。

## 2. 运行中

`trainer.py`在最终参数打印后自动保存到原训练logdir下：

```text
records/<UTC时间含微秒>_seed<seed>_pid<PID>/
    effective_config.json
    run_info.json
    result.json
```

- effective_config：JSON和CLI合并后的参数（每次seed和device已解析），不注入新训练参数。
- run_info：Git提交/分支/本地修改状态、Python/PyTorch/CUDA版本、所用GPU名称、命令、原train.log绝对路径。
- result：开始标running，每个任务正常评估完成后记录top1、Old/New、遗忘及耗时；正常结束才标completed。
  stage_mean_old/new只统计Task1以后，沿用现有grouped精度，不替代StageAudit的更高精度数据。
- 同配置再次运行也有独立目录，不覆盖旧结果；原train.log命名方式不改，手动重复prefix可能追加同一日志，
  以记录时间/PID和脚本时间戳区分；正式脚本已有独立prefix。
- 被杀死/异常退出时可能保留running和最后完整任务，**不表示进程仍活着**；回看原始报错判定。
  result completed指训练函数正常返回，不保证外层队列/W&B关闭一定成功。
- 元数据写入失败只warning，不中断训练；真实训练异常仍原样传播。没有后台监控、自动选模型或自动重跑。
- 不扫描环境变量或凭据，不每epoch做Git或GPU查询；启动时记录一次。预训练/数据划分哈希未知时为null，
  不编造。effective_config不展开代码内部所有隐式默认值，仍需保留代码提交。

等待队列时：lwait等待整个外层Bash PID，不等单个python子进程；队列结束后再pull，避免中途换代码。
本功能仅对更新后启动的进程生效，不补写、不重启正在训练的实验。

## 3. 收结果后

用户传回外层日志和本次records目录；若只有日志仍按日志整理，缺信息标未知，不强迫重跑。
先核对运行健康/配置/任务数，再做同机配对，最后回填**原实验ID**：保留、停止或待确认。
诊断不要求涨点，消融完整保留负结果，优化需同时看Average/Last与Old/New代价。
算法判定由研究分析完成，不由result.json的completed字段代替。

## 4. 哪些进Git

索引、实验卡、异常记录、配置配方、逐次目录和来源清单版本化。
raw/experiments中的大日志/附件/快照仅本地保留，Git仅纳入各目录的来源.md。
**Git clone不会下载原始材料**；需要复核时从清单原路径/本地归档取回，并核对SHA。
历史图表output也不在本次提交内。不要把Git当成原始实验数据的唯一备份。

当前仅等待004 CA与005覆盖率结果，不因新工作流再跑一遍已完成基线。
