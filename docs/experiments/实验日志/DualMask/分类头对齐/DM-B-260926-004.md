# CA真实新类特征：完整结果已回填，不替换基线

## 目的与唯一变量

检验原CA新类高斯近似是否值得替换，而不是再给骨干增加单向竞争损失。
基线 `ca_real_new_features=false`，候选 `true`。旧类仍使用已有高斯统计；
新类用当前训练数据统计流程提取的真实特征，每类有放回抽样256条。
仅当前任务CPU临时缓存，CA后清理；不新增旧图存储或推理前向。

固定：anchor5、Task0/增量20轮、CA5、math-SDPA、layer双冲突门、P LR0.02、
正则0.01；`old_competition_weight=0`，P方向修正关闭。数据路径读各机器JSON。
原有能量自适应和old-overlap强度适应保留，不能与005固定覆盖率混作单变量对照。

## 设计与实际执行的区别

实际脚本是每机重新训练Gaussian基线、再训练真实特征候选，共2次T10；
不是逐阶段checkpoint分叉。独立采样generator和保留高斯抽样调用，在CPU测试中
保持对应旧类采样与全局RNG，但不能据此承诺完整GPU训练轨迹逐位相同。
CA后分类头本来就可能不同，后续完整轨迹需要单独评估。

### 有效性与异常边界

- 两机分别Task0一致（3090 96.37；5090 96.81），不跨机相减。
- **3090 Task1首次CA前已不同**：post_merge Total 92.27858→92.20288（−0.07570pp，即1/1321个样本），Old 95.06532→94.92017，New均89.24051。同任务sample_sha256相同；不能用相同Task0证明完整轨迹相同，也不能将+0.068的Average精确归因于CA。原因未确定，不添加运行时相等断言。
- 5090 Task1首次CA前指标相同，但这不等于权重/logits逐位一致。后续任务已包含前序CA改变后的头，不是同一快照分叉。
- 所有4次运行内pre_merge→post_merge预测改变均为0，不支持合并造成主要精度损失。AppliedConflictBudget重构merge_error并非全为0（最高3.9204e-4），仅记录遥测，不称权重逐位一致；不能据它单独断言merge损坏。
- 5090耗时177.56 vs88.45分钟波动大，原因未确定，不作为真实特征CA提速证据。
- CA feature source日志确认为gaussian/real；每类256、旧类gaussian。上述均为单seed探索证据。

### 决策

**已完成、不替换B0。** 它不是完全无效：两机阶段New都有约1.2pp提升；但阶段Old均下降，Forgetting分别+0.9100/+1.1977，Average仅+0.068/+0.002，Last方向不一致。不能宣称“保Old同时提高New”，不补邻近混合系数网格，不把它接入覆盖率候选。Forgetting依赖历史峰值，和最终Old并非同一指标。

若后续验证训练期双向分类头约束，它仍是新假设，不能拿这次结果充当有效性证明。原Gaussian CA继续使用。
