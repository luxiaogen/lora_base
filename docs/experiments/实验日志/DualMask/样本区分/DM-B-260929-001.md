## 损失与梯度规则

对每个当前任务样本，归一化CLS特征，在整个当前batch内计算：

```text
positive = 除自身外同类样本的平均余弦相似度
negative = 异类样本的最高余弦相似度
hinge = max(0, negative - positive + 0.1)
loss = 有效anchor的hinge均值
```

没有正样本或没有负样本的anchor不计入分母；全部无效时返回可反传的有限零。
无效anchor仍可作为其他有效anchor的负样本。没有随机采样，不额外消耗RNG。
新增配置默认 `pair_separation_weight=0`（关闭）、`pair_separation_scope=p`、
`pair_separation_margin=0.1`。scope `sp` 选择当前S和P的B。

额外梯度通过 `autograd.grad` 获取，再加到原loss.backward产生的对应B.grad上，
随后仅调用一次原optimizer.step；不把新损失整体并入普通backward，避免误更新其他参数。
原分类与正则梯度继续正常训练S/P和当前分类头。P-only不是冻结S，
也不等于保证Old安全。门控、merge、CA和推理路径不改。
样本损失不乘CosFace scale；0.025/0.05是固定探索值，不是已知最优值。

## 运行命令（在原项目，使用当前conda环境）

3090：

```bash
lrun scripts/9_29_imgr10_pair_separation_3090.sh ./logs/9_29_imgr10_pair_separation_3090.log
```

5090：

```bash
lrun scripts/9_29_imgr10_pair_separation_5090.sh ./logs/9_29_imgr10_pair_separation_5090.log
```

无参数启动时，先对本机各variant做Task0–1各1epoch、CA1的执行短测（W&B offline、不保存权重）。
短测全部正常退出后自动运行固定正式队列；不根据任何准确率取消训练。
若短测有运行失败，停止启动正式队列，先修复技术问题。正式某组失败会记录并继续后续组，
整个队列最终返回非零；不会把失败伪装成全部成功。队列无需半夜人工按结果选下一组。

仅打印命令：`bash scripts/9_29_imgr10_pair_separation_3090.sh --dry-run`。
仅短测：同脚本加 `--smoke`。已完成短测需单独启动正式队列时加 `--full`。
5090同理。参数拼错退出，不意外启动训练；没有训练性能断言或运行时数值校验框架。

内部每组日志位于 `logs/shell_logs/imgr10_pair_separation_<GPU>/<时间戳_PID_模式>/`。
短测与正式prefix/log目录不同，每组命令、代码提交、退出状态均可追溯。
shell由研究技能的generate_sweep展开，随后补项目根目录、模式、短测与日志前缀；
修改JSON后需同步重新生成/保留包装逻辑，并运行队列测试，不能只改JSON。

## 记录与判读

每epoch文本日志记录 `pair_raw`、`pair_weighted`、`pair_valid_ratio`、`pair_active_ratio`；
后者分母为有效anchor，前者valid比例分母为全部样本。
各epoch统计为batch均值的平均，符合现有loss日志方式。
原有tracker会接收最后epoch的汇总指标，不声称新增了逐epochW&B曲线。
每个增量任务第1/10/20epoch的第1batch输出 `PairSeparationGrad`：
所选B分支的分类梯度范数、加权附加梯度范数、比例、夹角。
诊断不改变梯度/RNG，不额外前向。
