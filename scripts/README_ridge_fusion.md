# 正式 T10：DualMask + 固定 ViT Ridge 保守融合

这次不是读出诊断或 Oracle：启动 `main.py`，Task0–9 正常训练 LoRA、merge、CA；
最后的 `CNN top1 curve` / `Average Accuracy` 是实际融合候选的预测成绩。
同批图片在融合前保存原 DualMask 预测，`RidgeFusionResult` 给出同次运行的基线与候选对照，不重复训练基线。

## 唯一方法变化

不再猜哪一个专家答对，而是使用 Ridge 对**所有已见类别**的支持分数，保守补充 DualMask 分数：

```text
DualMask 已见类分数 → 每个样本在类别维度中心化、标准化
原始 AugReg ViT 特征 → Ridge 已见类分数 → 相同标准化
融合分数 = DualMask 标准化分数 + coefficient × Ridge 标准化分数
最终预测 = 融合分数最大的类别
```

coefficient=0 时完全返回原分数，不改变原预测或打破原平局规则。
Task0固定为0；Task1+在当前任务训练留出上，从预先固定的0/0.025/0.05/0.1/0.2选择。
目标是 `救回数量 − 3 × 弄错数量`；平局取更小系数、无净收益取0。
这是一个预先定义的训练侧选择规则，不按测试成绩挑系数，不强迫采用有害融合。
当前新类留出不覆盖旧类分布，所以该规则**不保证**不会伤Old，完整T10就是检验这点。

Ridge的alpha固定为1，来自上一轮两机Task0训练留出的相同选择；本轮不再扫alpha。
每任务仅复用当时当前训练集已经提取的原始W_pre特征，累计Gram与类别特征和，CPU双精度求解。
原始骨干始终不变，因此旧统计不需要随DualMask重提取；旧训练图片不再次读取。
外层校准样本从LoRA、CA统计、W_pre原型与Ridge拟合中都排除。
只在本任务CA完成后读取当前留出，确定系数、保存小型JSON策略，再进行正式融合测试。
预测函数仅接收两份分数与封存系数，不接收标签或任务ID；标签只用于训练侧校准及事后报告。

融合可能选择两个专家原先top1以外的类别，因此此前“两个top1正确并集”只是硬切换上界，
不是这类分数融合的严格上界。本实验不使用任何正确并集规则，也不把Oracle成绩当成候选成绩。

## 固定协议与分工

两机各一遍完整ImageNet-R T10、seed1993、anchor2.5、20轮、CA5、math-SDPA、原layer双门。
S/P更新、保护/冲突门、正则、学习率、合并及CA不改变。
不保存每任务权重、图片或稠密特征。长期统计约2.84MiB；另有当前768×已见类的Ridge读出在RAM。
正系数时每张图片需要两个骨干前向；Task0/零系数时只走原预测。这不是原方法的一次前向效率。

| 机器 | 校准排除 | 比较 |
| --- | --- | --- |
| 3090 | Task1+每类每20张留1张，延续005的约5%协议 | 同次原模型 vs 实际融合预测 |
| 5090 | Task1+每类每10张留1张，延续005的约10%协议 | 同次原模型 vs 实际融合预测 |

不同排除比例不横比两机绝对值；同seed两台不是多seed验证。
新同次原模型是配对基线，不能直接减去未留出的历史87.2。
普通训练结束/CA审计分数仍是原模型；正式评估CNN是融合候选。
`RidgeFusionResult`按原始样本计数计算，CNN沿用既有两位小数，平均可能有很小舍入差。

## 运行

默认先Task0–1各1轮的GPU短测，成功后自动进入完整T10。
短测只检查端到端路线，不能作为性能证据，也不按准确率设置中断断言。

```fish
bash scripts/10_01_imgr10_ridge_fusion_3090.sh
bash scripts/10_01_imgr10_ridge_fusion_5090.sh
```

`--smoke`只短测，`--t10`只完整训练，`--dry-run`只显示命令，不创建结果目录。
已有约80–90分钟的3090 T10为时间参照；新任务额外校准与融合评估可能增加耗时。
5090独享预计同量级，以实际GPU负载为准；这次不是约一分钟的固定读出任务。

输出在 `logs/shell_logs/imgr10_ridge_fusion_<machine>/<timestamp>/smoke|t10/`：

- `run.json`：提交、实际配置、命令、源文件SHA。
- `training.log`：真实训练和CNN候选曲线。
- `fusion/task_XX_policy.json`：测试前封存系数、训练留出救回/弄错、统计量字节数。
- `fusion/task_XX_result.json`：实际候选/同次基线的Total、Old、New、Average、Forgetting及救回/弄错。

保留标准：候选相对本次基线Average/Last净提高，不能只有New提高而Old明显下降。
若选择器多数取0或完整结果不升，如实说明没有验证有效取用信号，不继续用Oracle包装收益。
