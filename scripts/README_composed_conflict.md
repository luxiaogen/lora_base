# S/P 合成更新共享冲突门：3090 实际训练队列

本轮回到双分支的训练/合并机制，不添加教师、分类头损失、CA 改动或推理路由。
默认 `dual_mask_composed_conflict=off` 保持原算法，实验只启用 Task1–9。

## 候选的具体变化

先计算带 gamma 和原基础限制的更新：

```text
Us = gammaS × BS AS × S保护门
Up = gammaP × BP AP × P可塑区
U  = Us + Up

主候选分数 = W_pre重要性 × |U|
共享冲突门 G = 1 − beta × M
有效更新 = G × U
```

原算法分别对 S/P 选点，两个不同的冲突门可能破坏已有的抵消。例如 Us=10、Up=-9，
净更新为1；只把S乘0.5会变成-4，共享门乘0.5则为0.5。
**性质限于基础限制之后的净更新**：G在[0,1]内，不会改变净更新坐标的符号或放大绝对值。
这不等于证明这些更新对旧类安全，更不等于已经提点或证明文献创新性。

共享选点数 K = 原S、P独立冲突掩码坐标数的平均（整数向上取整）。原自适应参考预算继续使用原始分支更新；
六组仅替换共享门选点方式，不另扫比例/beta。S/P基础限制、A冻结、损失系数和CA不变。
原正则公式仍保留，其中safe update使用本次训练前向实际使用的共享门。

## 六组完整 T10，按此顺序

| 模式 | 评分/门控 | 检验什么 |
| --- | --- | --- |
| net | 重要性 × \|Us+Up\| | 主候选：合成后的实际净改动 |
| gross | 重要性 × (\|Us\|+\|Up\|) | 忽略抵消，但仍共用门；隔离净更新评分的作用 |
| magnitude | \|Us+Up\| | 去掉预训练重要性是否一样好 |
| uniform | 所有坐标均匀缩放 | 同一权重处，匹配net选点所移除的更新范数 |
| w_pre | 仅预训练重要性 | 当前净更新幅度是否提供额外信息 |
| random | 任务/层固定随机排名，选择相同K | 有依据的选点是否比随机选点更好 |

same-K和同移除范数都指**同一权重处的受控规则**；不同组训练轨迹不同，实际K/移除范数可能不同，必须同时报告。
随机评分仅用独立Generator，不改变全局随机状态；它不是每步随机重抽掩码。
不重复训练已完成的原基线。历史基线仅在本机数据、训练设置、类别顺序等可比时使用，不能横比5090成绩。

固定 ImageNet-R T10、seed1993、anchor2.5、20轮、CA5、math-SDPA、学习率0.02。
只支持本轮 layer、private=global、S/P冲突门开启、merge=suppress；冻结掩码/渐进门/残差/硬置零等其他候选关闭。
协议约束只在test中验证，不加入研究训练路径的防御式断言。
没有旧图片回放、测试标签选点、真实任务ID推理、额外教师前向或新增损失权重。
不保存checkpoint或稠密特征；本机JSON的数据/预训练路径不覆盖。

## 运行

从原项目、原实验分支运行，服务器训练环境激活后：

```bash
bash scripts/10_02_imgr10_composed_conflict_3090.sh
```

先跑net/uniform两组Task0–1各1轮GPU短测，成功后六组实际完整训练。
短测结果不能当正式成绩。默认约8小时：8小时之后不启动新的组，已经开始的完整训练不会被截断。
预计约7–9小时，实际取决于GPU与数据加载；未完成的模式会明确记录为`time_budget_pending`，不按准确率自动淘汰。
继续未完成的组：

```bash
bash scripts/10_02_imgr10_composed_conflict_3090.sh --mode t10 --only w_pre random
```

上述续跑模式名只是示例，应以queue.json实际未完成名单为准。

## 输出与解释边界

`logs/shell_logs/imgr10_composed_conflict_3090/<timestamp>/`：

- 每组`run.json`：提交、有效配置、本机路径、源文件SHA256、完整启动命令。
- 每组`training.log`；主目录`queue.json`：真实退出码、时长/待运行状态。
- 每组完成后更新`results.csv/json`、`gate_diagnostics.csv`、`comparison.png`。
- 图包含完整T10 Old–New、Average，以及同权重处原独立门的符号翻转反事实；不混入5090数据。

`ComposedConflict`日志直接用实际共享门；不沿用会重新选点的旧P诊断。
记录每层每任务的原独立门反事实放大/反向坐标数、共享门对应数量、净/分支幅度比、密度和移除范数。
这些反事实是在**候选本身训练后的权重**上算的，不是原基线轨迹，也不能直接证明遗忘原因。

保留候选需同时看本机Average/Last净提升，以及Old/遗忘是否保住、New是否改善。
net优于gross才支持显式考虑抵消有益；net优于magnitude/w_pre/random才支持组合评分；
net优于uniform才支持选择位置不只是缩小更新。否则如实收缩主张，不把数学性质包装成性能或新颖性。
