# 有限放行与控制器精简：双机夜间队列

这是新候选和归因实验，不是已验证的提点方法。两机分别同提交配对。
ImageNet-R T10、seed1993、anchor2.5、20 epochs、CA5、math-SDPA；不保存 checkpoint。
Task0、S 分支、冲突评分、优化器、CA、推理方式保持原样。增量 A 随机初始化后冻结，只训练 B。

## 放行的具体定义

仅 Task1–9 的 P 权限改变。第1轮按原硬补集训练；第1/5/10轮结束时刷新放行点，最后10轮不再刷新。
当前任务训练图片取确定性评估变换，按类别轮转取160张计算当前分类损失对 QKV 权重的梯度。
额外更新为 gamma_P × BA × protect × (1−alpha) × conflict_gate。
效用为负的「分类梯度 × 额外更新」，正值表示一阶近似上可能降低当前任务分类损失。

每层每 Q/K/V 最多放开保护区的10%，只挑正效用；数量不足就少选。
随机和幅度对照在各自同一状态用同一数量；不同训练轨迹不保证实际数量相同，必须报告实际计数。
随机使用独立 generator，位置对照为固定行/列置换，均不扰动训练 RNG。
P 放行点采用 S 的软保护强度，不是完全解除保护；原冲突门仍保留。

范数控制以同一 BA 下原 P 硬补集门控后的范数为目标，按层/QKV 仅缩小候选，系数不求导。
零增量时系数为1，保留 B 零初始化梯度。前向、正则和最终 merge 使用相同新规则；gamma 在门后乘。
这不是让不同模型的整个训练轨迹拥有同一更新范数。范数补偿会缩小未放行区域，也必须检查 New 是否真有净收益。

另外160张不重叠的当前训练图片用于记录放行前后分类损失；它们仍属于训练集，不冒充 holdout。
Task1/5/9、epoch1/5/10/20 在固定旧/新测试样本上作只读全已见类别 margin/预测诊断。
测试标签不决定放行位置、数量、超参数或队列顺序。每次恢复模式、requires_grad、Python/NumPy/Torch RNG。
不保存旧图片、逐样本历史特征或新的持久梯度矩阵。

## 固定控制器的边界

三个系数和 P rank 只在 Task1+ 覆盖原控制器输出，Task0 不变。
全固定组仍计算原 W_pre-NCM 诊断和原型，因此并未实现彻底删除该计算；其耗时标为 wpre_diagnostic。
收益若不足，固定设置只能列为精简候选，不宣称和原控制器等效。
CA 仍保存类均值/协方差，不声称整个方法没有二阶统计。

## 运行与预算

在各自原环境中：

```bash
bash scripts/10_04_imgr10_permission_release_3090.sh
bash scripts/10_04_imgr10_permission_release_5090.sh
```

每个配置先 Task0一轮、Task1两轮、CA一轮 GPU 短测，验证刷新后仍能训练；短测准确率不筛选方案。
全部短测通过才启动本机正式 T10。首个短测开始计10小时；截止后不启动新组，活动组完整结束。
正式异常暂停该机，保留错误，不自动重试。预算未启动项记 pending，不是负结果。
预计3090约9–11小时，5090约10小时左右；实际速度以首个完整组校正，不保证12组都在截止前启动。

输出 `logs/shell_logs/imgr10_permission_release_<machine>/<timestamp>/`。
manifest/active/smoke_queue/queue JSON 记录真实 PID 和状态；每组 run.json/training.log 保存源码、配置、硬件指纹。
完成一组更新 results/report 和逐任务、范数、margin、耗时/存储/GPU峰值图。只比较完整匹配 T10。

```bash
python scripts/analyze_permission_release.py <输出目录> --machine 3090
```

## 预登记的取舍

放行只有同时优于原基线、随机与幅度对照，并保住 Old、Average/Last 有净收益，才支持进一步研究。
只提高 New、损失 Old，不视为解决取舍；放行点的正训练效用也不证明旧类安全。
原/打乱 P 位置配对不能推广为「整体 W_pre 无用/有效」，其他先验仍保留。
一轮单 seed 小差异不宣称显著、等效或创新成立；今晚不自动替换正式基线。
